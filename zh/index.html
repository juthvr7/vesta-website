01 / 命题

世界构建工具应该彼此组合，而不是继续割裂。

地形、几何、栅格处理、资产放置与引擎交付通常各自为岛。Vesta 把它们连接成一条持久链路——从创作意图到可复现结果。

Vesta 的不同之处

01

一份源数据

版本化 Graph 在所有宿主中保持权威。

02

一套运行时

验证、规划、执行、缓存与诊断统一归属 Core。

03

多种结果

同一个系统可以输出几何、场、世界或引擎可消费的数据。

02系统链路

让意图成为可复现的结果。

每次请求只走一条可观察的执行链。不隐藏引擎分支，也不复制节点语义。

01

创作

类型化端口、稳定身份与版本化参数。

02

验证

只有结构化诊断通过，才允许生成计划。

03

规划与求值

显式后端、范围、LOD、Seed、预算与缓存。

04

交付

向 Studio、CLI、Worker 或引擎适配器返回不可变类型化结果。

03统一空间数据

数据各有语义，执行共享语言。

Heightfield 不是普通图片，Mask 也不是 Field。Vesta 显式保留它们的语义，同时让所有数据进入同一套类型化 Graph 与求值模型。

04Vesta Studio

把它做成真正的桌面创作工具。

Studio 是围绕同一套 Core 构建的创作宿主，自动化与未来的引擎适配器也使用这套 Core。工作区、Dock、视口、CPU 参考预览与算子开发工具已经运行；创作能力与输入门禁仍在持续推进。

01原生桌面

Rust + Bevy/wgpu 应用

02共享权威

UI 不拥有第二套 Graph Runtime

03保持响应

长时间求值不会阻塞 UI 主线程
